# 0.7.0 — Airflow-Host Notification Core

## Added

- PostgreSQL-backed `zacks_core` notification schema.
- Internal `zacks-notification-api` observation service.
- Singleton `zacks-notification-worker` for subscription synchronization,
  Tencent SES delivery, delivery-status reconciliation, quotas, weather policy,
  and incident recording.
- Redis database 1 as an optional wake-up layer with PostgreSQL polling fallback.
- Authenticated Cloudflare active-subscription snapshot endpoint for reversible
  migration of current Web users.
- Reversible migration commands for shadow mode, synchronization, cutover,
  status, and rollback.

## Changed

- Venue observations can be switched from the Cloudflare Worker to the local
  Docker-network API without changing any DAG or polling schedule.
- WeChat suppresses only on a fresh authoritative negative subscription gate.
  Missing, stale, or non-authoritative gate state fails open.
- Cloudflare becomes an edge and temporary enrollment compatibility layer; it
  is no longer required for the notification hot path after cutover.

## Safety

- Existing D1 `subscription_events` are imported before cutover to prevent
  duplicate mail.
- Expired in-flight email leases are marked uncertain and are not blindly
  replayed.
- The release does not delete D1 data and does not send synthetic email or
  WeChat probes.
