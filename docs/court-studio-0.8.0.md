# Court Studio 0.8.0 — design and release contract

## Scope and baseline

User request: complete the pending UI redesign, merge it, deploy through GitHub
and repeat failed checks until the application works. Main was accepted 0.7.0
at 82dc360b70aa18d1fee9e08745f6065d559cd7d6. The design branch contained only
baseline-capture/development preparation, not a finished UI; this change adds
that implementation. The actual baseline screenshots were reviewed.

## Design

Warm neutral canvas, forest/teal actions, restrained tennis references and
readable hierarchy. Homepage explains the product before showing telemetry;
desktop has a narrow creation pane and wide searchable venue directory. Mobile
has a fixed, safe-area-aware navigation outside the transformed scroll surface.
Primary creation stays reachable, including small screens. Lulu remains stateful.
Search and subscribed/attention filters are entirely local. A failed/stale read
never becomes healthy. The service is alerts, not booking: there are no invented
live slots, no fake social proof, and no client-side API semantic changes.

## Functional safeguards

Email verification, quick-venue selection, weekday presets, time validity,
subscription limits/duplicates, cancellation confirmation, tiers, admin
permissions, masked identities, coffee QR timing and receipt storage remain.
Email edits clear the previous challenge. Time labels mean the desired booking
time, not notification time. Reduced motion, native keyboard behavior and all
28 protected mobile runtime hashes remain unchanged.

## Verification and production

CI now runs every Playwright suite, including mocked full verification/create/
cancel flows, responsive checks, local filtering and stale/error behavior.
Mock API routes prevent real test sends. Public acceptance uses fresh anonymous
contexts, blocks every mutating HTTP method and tests desktop/390px/320px views,
exact edge identity, real bootstrap rendering, search, empty recovery, quick
verification entry and More/help permissions. Screenshots and sanitized JSON
are archived. This does not claim a real verification-email-to-inbox test.

0.8.0 uses the existing protected web-only release path. Web and host identities
are deliberately separate: unchanged Host Core/Airflow/Sender stay on accepted
0.7.0. No D1 import, migration, secret rotation, consumer pause or real test send.
The public browser gate must pass before the release-tag job can run. If Web
fails, preserve evidence, fix forward, run exact-SHA CI and reapply the protected
Web release. An approved rollback is the previous Web commit through the same
protected Web workflow; it must not restore a business database.

The isolated local workspace has no Docker or network access and cannot run the
complete make verify gate. Local production builds, runtime hash checks,
source contracts and offline browser rendering are development evidence only.
Exact-SHA GitHub CI and public deployment checks remain required. This document
is a contract, not a claim that deployment has already succeeded; the final
Release Control record supplies actual SHA, run IDs and results.

## Release review corrections

CI on the first candidate exposed a version test pinned to 0.7.0; it now checks
project/runtime/latest-changelog consistency. Full browser CI then exposed stale
snapshots still being labeled healthy. Stale/loading/unknown venue health is now
unknown, the current healthy total is withheld, and Lulu does not claim to be
watching when the latest state is unavailable. A regression covers recovery to
live data and the attention filter.

The heading test now allows the accessible-name whitespace generated by a line
break. The device-fixture backdrop test clicks inside the actual rounded screen
instead of its clipped corner. Additional desktop/mobile product backdrop tests
exercise genuine clicks with no forced events, no writes and no runtime edits.
Failure screenshots and traces are retained. These are fixes to be validated,
not claims that the final production release has already passed.
